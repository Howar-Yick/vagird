## VA 有效预算口径

state 新增 `_va_budget`（schema=1）：

- `periods`：当前宏观周期有效 VA 期数。
- `weekly_budgets`：ISO 年/周键→当期已记预算；`total` 为这些预算之和。
- `excluded_weeks`：观察到关闭/迁移阻断的周；`last_observed_week` 防止回退日期补记暂停周。
- `cycles`：已结束周期预算历史；`migration` 保留证据和来源指纹。
- `status=ready/pending`：pending 只阻断 VA 目标调整/启动修复，不影响普通网格或宏观止盈。

有效期 n 的预算为 `dingtou_base × (1 + dingtou_rate)^n`，n 从 1 起。关闭期间不增加预算、不增长 n；恢复后接续 n。目标仍是 `initial_position_value + total`，保留原 VA 按价格变化增减底仓的逻辑，没有按恢复时市值重锚。

每个观察到的有效交易周最多记一次；不遍历缺失周补投。同周先关闭再开启可记一次，已记预算不因关闭撤回，同周反复开关不重复记。跨年使用 ISO 年而非公历年。热加载更改金额/增长率只影响以后新增的预算，不重算已记历史预算；这是预算持久化后的明确口径。

`trade_week_set` 继续按旧函数推进，供宏观冷却、期限和滴灌使用。VA 暂停不冻结、不删周。滴灌仍每个观察交易周释放一次到 `initial_position_value`；释放资金不再加入 VA 的 `total`，因此不重复记为定投。

宏观止盈真实成交确认完成后，按原逻辑重锚和建立“实际卖出现金+旧未释放池”的新滴灌池，再归档并清零当前 VA 预算/增长期数。历史周期里本周已记过 VA 的，新周期本周不再次记，下一有效周从第 1 期开始。未核验迁移不能通过一次止盈隐式变为 ready。

新 CSV 写入 `reports/<symbol>.va31416.csv`，保留旧 CSV；列名改为“VA有效期数”“当周已记VA预算”“累计VA预算非成交投入”。HTML 同口径。待迁移预算显示待核验/空值，关闭期间新预算为零，过去已记预算仍可显示；没有伪称已成交投入。

## 旧 state 迁移

已有 `_va_budget` 且校验通过：直接恢复，不重算、不覆盖。无历史周的全新 state：从 0 开始。已有历史周但没有有效 VA 预算：默认 pending，不凭当前 true 或日报理论金额认定历史全部开启。

这会按旧 `trade_week_set` 和保存的定投参数重建预算，目标和执行保持旧公式；不修改初始价值、底仓、Stack、券商成本或 PnL。当前配置本来关闭或属于已确认关闭名单的标的，不接受 always_enabled 模式。

关闭旧标的必须补齐首次暂停前后的配置/开关日志、当时 state、此后每段开关和宏观重锚记录，核验当前周期每个有效周预算。使用 `mode=verified_budget`，提供完整有效周→金额映射 `weekly_budgets`，同时提供来源指纹和证据说明。没有证据时保持 pending；即使误改 true，也不会按旧公式补投。

指纹算法为：

```python
hashlib.sha256(json.dumps(saved_state, sort_keys=True, ensure_ascii=True).encode()).hexdigest()
```

示例仅绑定 10/9 state。真正升级前必须暂停策略调度、只读获取最新 state，再按同一算法重新绑定；不能拿 10/9 state 覆盖新成交后的 state。pending 在重启/新增交易周后保留原指纹，补证据时核对它的 `source_sha256` 和 `legacy_weeks`，不是任意换成后来 state 的指纹。热加载可应用核验好的迁移声明，声明本身不自动将 VA 开关改 true。

## 动态上限：参数未确认，示例未启用

现行配置完全未更改。代码缺省/示例 `enabled=false` 时保留旧容量和订单行为；开启动态模式须先确认参数及 PTRADE 数据口径。以下是推荐值，只有动态约束原则已确认，数值均未获用户确认：

| 参数 | 推荐值 | 依据 |
|---|---:|---|
| reference_assets | 1,000,000 元 | 参考尺度，非声称实际账户为100万 |
| cap_at_reference | 5,000 元 | 在参考尺度延续旧上限，等价资产比例0.5% |
| capital_budget_ratio | 0.5 | 最多分配总资产一半作为结构网格预算 |
| unit_budget_fraction | 0.02 | 每个网格单位最多占结构预算2%，保留多档余量 |
| cash_reserve | 10,000 元 | 演示安全现金线，需按实际账户和用途确认 |
| fee_buffer_rate | 0.001 | 名义买单金额加0.1%支付缓冲，需核对实际券商费率 |

结构流动资产 = `max(0, available_cash − cash_reserve) + 策略ETF持仓数量 × 有效行情`；只统计策略 ETF，不将 GC001/逆回购、其他账户资产直接作为可用现金。

```
结构资金预算 = min(总资产 × capital_budget_ratio, 结构流动资产)
网格金额上限 = min(cap_at_reference × 总资产 / reference_assets,
                  结构资金预算 × unit_budget_fraction)
```

持仓价值只用于结构单位和卖侧容量，不能支付买单。即时买单使用券商 `available_cash`（须确认已扣冻结）减现金安全线，再扣本地未反映的委托；全账户挂单与本地保留账按委托号取并集。部分成交从保留账转为已支出，避免同时算成冻结；订单先可见/先终态而现金滞后时，总池上界阻止资金复用。缺终态明细按整笔已花费保守处理，确认现金前不放大池；可能暂时少用资金。重启时从券商当前现金/全账户挂单重建，须先确认快照一致。

所有真实发送入口仍满足原仓位和守门条件，再按**最终限价**取100份整手：名义金额不超过动态上限；买单还满足包含费用缓冲的即时支付约束。允许缩小本次订单，不修改结构单位；少于100份或名义金额低于1000元就阻断该单。上限低于最低网格时，结构单位回退旧尺度并由发送门阻断不合规订单，不静默把上限抬高发单。

现金低、资金转入未到期 GC001 不使网格单位/卖侧自动归零。已到期现金也只有出现在券商即时可用现金里才能用于买单，不自行推算到期。多标的按原扫描顺序竞争共享池，没有每只重复分配同一现金，也没有新增公平轮转策略。

总资产/行情缺失或异常：结构单位回退旧5000尺度并记录原因，阻断新增买单；异常卖侧按旧上限和整手规则回退。动态参数非法时阻断发送。订单返回异常保留原涨跌停冷却路径，且本实例后续买单暂停，需人工核对券商挂单后再重启，避免不明成交窗口重复使用预算。

实现读取 `context.portfolio.total_value`、`available_cash`、`get_position` 和全账户 `get_open_orders()`。快照不能证明这些字段在用户券商端的实时语义；启用前必须只读核验账户总资产字段、现金是否净扣冻结、订单剩余成交量/状态/手续费。缺失字段会记录原因并阻断买侧；不要替换成包含未到期逆回购的余额来绕过检查。
